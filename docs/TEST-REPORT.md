# Loom 테스트 리포트

검토일: 2026-08-05
검토 방법: `python3 -m http.server 8080 --directory Deliverable/` 로 `http://localhost:8080/loom/`를 열어 GitHub Pages `/loom/` 하위 경로를 재현. 자동화 브라우저(데스크톱, 마우스/JS 이벤트 기반)로 기능을 검증하고, 정적 검사는 `grep`으로 실행. 실제 iPhone 터치·회전·IME는 이 환경에서 검증할 수 없어 Pending으로 분리했습니다.

---

## 고친 문제

자체 검토 중 실제로 발견해 고친 문제들입니다.

1. **빈 시간대 탭이 씹힘** — 블록을 담는 `.lanes` 레이어가 투명하지만 자기 영역 전체의 클릭을 가로채서, 블록이 없는 빈 시간대를 탭해도 새 블록 시트가 열리지 않았습니다. `.lanes`에 `pointer-events:none`, 블록·+N 칩 같은 실제 자식에는 `pointer-events:auto`를 줘서 고쳤습니다.
2. **같은 이유로 빈 날 안내 문구도 탭을 가로챔** — `.empty-hint`도 같은 방식으로 고쳤습니다.
3. **글자 크기 설정이 시간축에만 적용되고 헤더·Now&Next·하단 바·시트에는 반영 안 됨** — `--f` 변수를 시간축(`#grid`)에만 지정하고 있었습니다. 앱 전체를 감싸는 `#app-root`에 지정하도록 옮겨서, 6~17px 모든 단계가 화면 전체에 일관되게 적용되도록 고쳤습니다.
4. **키보드로 블록을 이동/길이 조절하면 포커스를 잃음** — `↑`/`↓`로 블록을 옮기면 다시 그려지면서 포커스가 `<body>`로 빠졌습니다. 이동 전 포커스된 블록 id를 기억해뒀다가 다시 그린 뒤 같은 id의 블록에 포커스를 돌려주도록 고쳤습니다.
5. **`innerHTML = ""` 사용이 지시서의 자동 검사에 걸림** — 사용자 입력을 넣는 곳은 원래부터 전부 `textContent`/`createElement`였지만, DOM을 비울 때 쓴 `el.innerHTML = ""` 몇 곳이 `grep -rnE 'innerHTML'` 검사에 걸렸습니다. 전부 `el.replaceChildren()`으로 바꿨습니다 (동작은 동일, 안전한 표준 API).

## 고친 문제

배포 전에 직접 찾아 고친 것들입니다. 앞의 세 가지는 고치지 않았다면 앱이 멈추거나 데이터가 사라졌을 문제입니다.

0. **★ 공용 모듈을 정적 `import` 해서, 그 파일 하나를 못 받으면 앱이 빈 화면이 됐습니다.**
   `sync.js`가 `import * as Shared from "../../shared/v1/sync.js"`로 시작하면, `app.js` → `sync-runner.js` → `sync.js`로 이어지는 모듈 그래프가 통째로 실패합니다. 오프라인 첫 실행, 404, Service Worker 캐시 실패 어느 것이든 걸립니다. loom은 원래 저장소 밖 파일에 하나도 기대지 않는 앱이었으므로 이것은 동기화를 붙이면서 새로 생긴 문제였습니다. 공용 모듈을 지우고 앱을 띄워 **실제로 빈 화면을 재현한 뒤** 고쳤습니다.
   → 통신이 필요한 순간에만 **동적 `import`** 로 부르고, 실패하면 동기화만 쉬게 했습니다. 컨텍스트 ID·라벨·파일 경로처럼 localStorage만 쓰는 부분은 loom 안에서 직접 처리해 공용 모듈 없이도 읽히게 했습니다(키 이름이 `shared/v1` 소스와 같은지 검사에서 대조합니다).
1. **★ Service Worker가 GitHub API 읽기를 전부 막고 있었습니다.**
   기존 `fetch` 핸들러는 오리진을 가리지 않고 **모든 GET**을 가로채 캐시에서만 응답하고, 없으면 `Response.error()`를 돌려줬습니다(주석에도 "Network is never used"). 반면 쓰기(PUT/DELETE)는 `method !== "GET"`으로 그냥 통과합니다. 그래서 **읽기만 실패하고 쓰기는 되는 반쪽 상태**가 됩니다. 이 상태에서 올리기를 하면 `readFile()`이 실패해 "원격에 파일이 없다"고 판단하고, 합칠 대상 없이 빈 내용을 써서 원격 기록을 지웁니다.
   → `url.origin !== self.location.origin`이면 핸들러가 손대지 않고 통과시키도록 고쳤습니다. 같은 오리진에는 네트워크 폴백을 더해 공용 모듈이 캐시에 없어도 받아올 수 있게 했습니다.
2. **★ CSP `connect-src`가 `'self'`뿐이었습니다.** `https://api.github.com`을 추가했습니다. 없으면 요청이 아예 나가지 않고 화면에는 `Network unavailable`로만 보입니다. 1번과 증상이 똑같아 따로 고쳤다면 원인을 찾기 어려웠을 것입니다.
3. **템플릿에 `updatedAt`이 없어 병합 기준이 없었습니다.** 사용자가 편집·생성하는 세 지점에서 `updatedAt`을 찍고, 값이 없는 템플릿(기본 Weekday/Weekend)은 항상 지는 쪽으로 두었습니다.
4. **토큰 입력칸이 스타일을 못 받고 있었습니다.** `app.css`의 입력 규칙에 `input[type="password"]`가 빠져 있어 44px 최소 높이가 적용되지 않았습니다.
5. **설정 시트를 닫아도 동기화 상태 리스너가 남았습니다.** 사라진 DOM을 계속 참조하게 되어, 닫을 때 해제하도록 고쳤습니다.
6. **동기화를 켜는 순간 공용 모듈을 못 받으면 처리되지 않은 오류가 났습니다.** 스위치가 켜진 것도 꺼진 것도 아닌 상태가 됐습니다. 실패하면 꺼진 채로 두고 화면에 사유를 보여 주도록 고쳤습니다.

## 알면서 그대로 둔 것

- **삭제는 기기 간에 전파되지 않습니다.** 올리기가 기록을 줄이지 못하게 막은 결과입니다. `Clear today`·`Delete data before…`·`Reset everything`으로 지운 블록은 다른 기기에서 동기화하면 되살아납니다. 기록이 사라지는 쪽보다 남는 쪽을 택했습니다. 맞추려면 tide처럼 tombstone이 필요합니다.
- **표시 설정(글자 크기·시간 간격)은 올리기만 하고 받을 때 적용하지 않습니다.** 기기마다 다른 값이 맞다고 보았습니다. 백업에는 담겨 있어 복원할 수 있습니다.
